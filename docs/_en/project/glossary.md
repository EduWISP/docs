# Glossary

| Term | Meaning in EduWISP |
|---|---|
| **ADR** | Architecture Decision Record: a short document recording a design decision, its context and consequences. |
| **Scope** | Context a policy belongs to: security, education or family. |
| **Android Enterprise** | Android features for managing corporate or institution-owned devices. |
| **AMAPI** | Android Management API: proprietary Google service to manage Android Enterprise devices. Excluded from the EduWISP core (ADR-0009). |
| **DPC** | Device Policy Controller: the app managing the device as *device owner*. In EduWISP: the open-source **EduWISP DPC**. |
| **Security baseline** | Minimum set of rules that no less-privileged policy can weaken. |
| **DPIA** | Data Protection Impact Assessment under the GDPR. |
| **DPO** | Data Protection Officer of the school. |
| **Enrollment / provisioning** | Procedure that registers a device and brings it under management. |
| **Fully Managed** | Android Enterprise mode in which the whole device is managed by the owning organisation. |
| **GMS** | Google Mobile Services. |
| **School / site** | The educational institution (*istituto*) and its physical sites (*plessi*). |
| **Kiosk** | Mode restricting the device to one or a few apps. |
| **Managed configuration** | App configuration set centrally by the MDM, when supported by the app. |
| **MDM** | Mobile Device Management. |
| **Effective policy** | Result of composing all policies applicable to a device at a given time. |
| **Provider adapter** | Component translating EduWISP's canonical model into a specific Android provider's features. |
| **Self-hosted** | Installation run by a school, a school network or a chosen provider. |
| **Tenant** | Unit of data isolation (typically a school or school network). |
