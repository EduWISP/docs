# Android management

## Target

School-owned Android tablets, managed as **Fully Managed** (*device owner*), with or without Google Mobile Services (proposal: ADR-0003).

## Technical approach

Under ADR-0009 every component must be open source and free of charge. Management therefore relies on components built by the project:

| Component | Role |
|---|---|
| **EduWISP DPC** | Open-source app installed as *device owner*: enforces policies, restrictions, kiosk, updates and time slots, offline too |
| **Server-agent protocol** | Open, documented, versioned interface between the EduWISP server and the DPC |
| **EduWISP app catalogue** | Repository of signed APKs (F-Droid-like) from which the DPC silently installs and updates apps |
| **Provisioning** | QR code generated by the EduWISP server, which downloads and installs the DPC on first boot |

## Android Management API

**Excluded from the core.** It is a proprietary Google service restricted to commercial EMMs, OEMs and Device Trust providers, with approval-based quotas and data processed by Google. It stays in the matrix only for comparison.

## Open risk: devices with Google services

On GMS devices, Play Protect only allows DPCs approved by Android Enterprise during enrollment. The main path is **getting the EduWISP DPC verified** by Android Enterprise; devices must stay as sold, with no unlocking or modified OS (ADR-0003, RNF-016).

## Provider abstraction

EduWISP's data model and policies stay independent of the agent. An adapter translates canonical intents into supported features and explicitly reports unavailable ones.
